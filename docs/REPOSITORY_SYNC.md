# همگام‌سازی مخزن خصوصی و GitHub عمومی

مخزن اصلی روی شاخه `test` در `https://git.cloubit.com/saanapp/mono.git` است. مخزن عمومی `https://github.com/cloudyhope/saan_cloud.git` نیز شاخه `test` دارد. دو شاخه در هر انتشار **درخت فایل یکسان** دارند، اما تاریخچه commit یکسان ندارند: GitHub با snapshot تازه آغاز شد، زیرا تاریخچه قدیمی مونوریپو شامل دیتابیس، کلید خصوصی، اعتبارنامه و نشانی submodule دارای اعتبارنامه بود. تاریخچه قدیمی را مستقیم به GitHub push نکنید.

برای انتشار تغییر بعدی از شاخه خصوصی `test`:

1. کد را تغییر دهید، آزمون‌های مرتبط را اجرا کنید و بازبینی راز/داده شخصی را انجام دهید. فایل‌های محلی و داده واقعی را وارد Git نکنید.
2. تغییرات را در `test` commit کنید و از تمیز بودن `git status --porcelain` مطمئن شوید.
3. `python scripts/check_public_snapshot.py HEAD` و در صورت امکان اسکنر تخصصی راز را اجرا کنید.
4. از ریشه مونوریپو `pwsh -File scripts/sync-repositories.ps1 -DryRun` و سپس `pwsh -File scripts/sync-repositories.ps1` را اجرا کنید.
5. SHA درخت دو شاخه را با `git rev-parse test^{tree}` و `git rev-parse refs/remotes/github/test^{tree}` پس از fetch تطبیق دهید.

اسکریپت ابتدا `origin/test` را با commit اصلی جلو می‌برد، سپس همان درخت فایل را به‌عنوان commit جدیدِ فرزند آخرین snapshot روی `github/test` می‌فرستد. انتشار بین دو میزبان اتمیک نیست؛ اگر push دوم شکست بخورد، پس از رفع مشکل همان اسکریپت را دوباره اجرا کنید. GitHub را با `git push github test:test` یا تنظیم چند `pushurl` روی `origin` به‌روزرسانی نکنید؛ آن فرمان تاریخچه خصوصی را عمومی می‌کند.

پیش از استفاده عملی از سرویس‌ها، تمام کلیدها و اعتبارنامه‌هایی که در تاریخچه خصوصی قدیمی وجود داشته‌اند باید **چرخانده شوند**: امضای/RSA کیف پول، پیامک، storage و نشانی‌های دارای token. مقدارهای تازه فقط در secret store محیط قرار بگیرند. حذف از آخرین commit اعتبار مقادیر قدیمی را باطل نمی‌کند. وضعیت پذیرش محصول در [HANDOFF](../HANDOFF.md) و [چک‌لیست ریلیز](RELEASE_CHECKLIST.md) جدا از همگام‌سازی مخزن است.
