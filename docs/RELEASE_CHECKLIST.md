# پذیرش و آمادگی ریلیز سان اپ

این چک‌لیست معیار خروج برنامه جامع است. گزینه علامت‌نخورده هنوز تأیید نشده است. آزمون‌های این سند باید با نسخه مشخص، نقش، داده ورودی، نتیجه مورد انتظار و شاهد ثبت شوند. نتایج هر اجرای واقعی در [HANDOFF](../HANDOFF.md) ثبت می‌شود.

## امنیت و نقش‌ها

- [ ] کاربر ناشناس هیچ داده عملیاتی و اطلاعات حساس کاربران را دریافت نمی‌کند؛ ورود عمومی فقط مسیرهای لازم دارد.
- [ ] رمز یا hash رمز، OTP، token و داده داخلی دسترسی در پاسخ عمومی، فایل داده، گزارش یا log نیست.
- [ ] مجوز همه متدها و مسیرها، دانلود رسانه، حساب غیرفعال، پروژه دیگر و کاربر بی‌نقش آزموده شده است.
- [ ] نقش ادمین، برنامه‌ریز، سرپرست، اکسپرت، کلاینت و حساب چندنقشی، هم در UI و هم API بررسی شده‌اند.
- [ ] کلاینت و اکسپرت با تغییر id به رکورد دیگری دسترسی ندارند؛ انتقال مدیریت دامنه جاری و سوابق را درست اعمال می‌کند.
- [ ] منو، route guard و API هم‌خوان‌اند؛ نبود منو و refresh یا تغییر نقش دسترسی اضافی نمی‌دهد.
- [ ] OTP، رمز، انتخاب پروژه، refresh، logout و ابطال نشست، محدودیت تلاش و retry درست کار می‌کنند.

## داده و چرخه خدمت

- [ ] کلاینت مدیر یا پیمانکار، نماینده، چند ساختمان، چند آسانسور، قطعات هم‌مدل با SN متفاوت و انتقال مدیریت پوشش داده شده‌اند.
- [ ] نصب، تعویض، قطعه امانی و سوابق پیش از انتقال قابل ردیابی‌اند؛ قید سریال و روابط نامعتبر آزموده شده است.
- [ ] درخواست کلاینت → بررسی ادمین → تخصیص → انجام اکسپرت → بررسی و اصلاح گزارش → نتیجه کلاینت کامل اجرا شده است.
- [ ] ثبت چندردیفی و Excel، خطای جزئی، موعد آینده و عقب‌افتاده، لغو، توقف، عدم دسترسی، انتظار قطعه و مراجعه مجدد کار می‌کنند.
- [ ] تمام انواع سؤال، صفر و false، شرطی و اجباری، حداقل عکس و کنترل ایمنی سمت سرور آزموده شده‌اند.
- [ ] داده هر آسانسور و قطعه مستقل است؛ تغییر قالب گزارش گذشته را عوض نمی‌کند و تأیید گزارش آن را قفل می‌کند.
- [ ] دوبار کلیک، refresh، retry، ارسال هم‌زمان و تکراری، پاسخ و خدمت و گردش انبار تکراری ایجاد نمی‌کنند.
- [ ] گارانتی، ادعای پوشش، تعمیر برد، دریافت و آزمون و تحویل، برگشت و امانت در دامنه ریلیز اجرا شده‌اند.
- [ ] انبار و موجودی کارشناس، مصرف، انتقال، برگشت و موجودی منفی و هم‌زمانی کنترل شده‌اند.
- [ ] پشتیبانی تلفنی، تیکت، پیام، اعلان، برآورد و مالی مصوب با ارتباط درست به پرونده کار می‌کنند.

## ادمین و موبایل

- [ ] فهرست‌ها، جدول، فیلتر، فرم، input، dropdown، دکمه و سایدبار ادمین در تمام بخش‌ها بررسی شده‌اند.
- [ ] جزئیات فروشگاه، مشتری، ساختمان، آسانسور، ویزیت، پرسشنامه، تیکت و کالا با داده کم و زیاد پذیرفته شده‌اند.
- [ ] اپ مشترک، تمام صفحات کلاینت و اکسپرت و تغییر نقش و پروژه با منوی درست پذیرفته شده‌اند.
- [ ] موبایل کوچک و بزرگ، landscape، فونت بزرگ، صفحه‌کلید، safe area، RTL و LTR و متن بلند بدون اختلال است.
- [ ] loading، empty، error، retry، disabled، success، offline و حفظ پیش‌نویس آزموده شده‌اند.
- [ ] دوربین، GPS، چند فایل، اندازه و MIME نامعتبر، ارسال ناقص و دسترسی رسانه بررسی شده‌اند.
- [ ] focus، صفحه‌کلید، label، کنتراست و خوانش خطا با فناوری کمکی بررسی شده‌اند.

## عملیات و انتشار

- [ ] محیط از مونوریپو قابل اجراست؛ جیبک و سرویس‌های قدیمی در stack فعال نیستند.
- [ ] seed محلی تکرارپذیر و محافظت‌شده است؛ راز و اطلاعات شخصی وارد Git نشده است.
- [ ] migrations روی نسخه هم‌نوع دیتابیس تولید تمرین، شمارش و روابط قبل و بعد تطبیق و rollback مشخص شده است.
- [ ] CI، buildها، آزمون API و سناریوهای بیزینس و بصری موفق و وابستگی‌ها بررسی شده‌اند.
- [ ] سرویس فایل، پیامک و وابستگی‌های بیرونی در staging با تنظیم درست اجرا شده‌اند.
- [ ] DEBUG خاموش، میزبان‌ها و originها محدود، رازها خارج کد، log و monitoring بدون اطلاعات حساس است.
- [ ] backup و restore واقعی، نسخه انتشار، health، هشدار و برنامه rollback تأیید شده‌اند.
- [ ] همه P0ها بسته‌اند و دامنه خدمات وعده‌داده‌شده آزمون پایان‌به‌پایان دارد؛ تأیید مالک محصول ثبت شده است.

آزمون local با SQLite به‌تنهایی برای تأیید migrations، concurrency و رفتار دیتابیس تولید کافی نیست. مسیرهای تولید در بررسی قبلی عمدتاً خواندنی و با نقش Manager بررسی شده‌اند؛ نقش‌های واقعی کلاینت و اکسپرت و نوشتن تولید تأیید نشده‌اند.
