# الزامات طراحی و تجربه کاربری سان اپ

این سند معیار اصلاح ادمین و اپ مشترک کلاینت و اکسپرت است. هدف، رابط مدرن و منسجم با سلسله‌مراتب واضح و اجرای سریع کار روزانه است. بهتر شدن چند صفحه معیار تکمیل طراحی همه محصول نیست.

## پایه طراحی

- فونت فارسی خوانا، مقیاس عنوان و متن، رنگ و فاصله‌های ثابت، radius و سایه کنترل‌شده، آیکون‌های هم‌خانواده.
- وضعیت‌های خدمت، تأیید، خطا و انتظار با متن و نشانه همراه رنگ؛ اطلاعات مهم بدون وابستگی به رنگ قابل درک باشند.
- اجزای مشترک: صفحه و header، کارت، جدول، فیلتر، فرم و خطا، select، تاریخ، دکمه، modal، tab، timeline، جزئیات، بارگذاری، empty و retry.
- RTL صحیح، مقادیر تلفن، شناسه، SN و PN با جهت مناسب، متن بلند بدون برش اطلاعات مهم.
- اصلاح تدریجی اجزای موجود و کاهش CSS و markup تکراری؛ ثبت قرارداد رفتار هر جزء.

## ادمین

| نوع صفحه یا جزء | معیار اصلاح |
| --- | --- |
| سایدبار | داده از بک‌اند، آیکون واقعی، گروه‌بندی، باز و بسته شدن، گروه مسیر فعال، رفتار مناسب دسکتاپ و موبایل |
| جدول | header خوانا، عرض منطقی، تراکم متعادل، عملیات ثابت، مقدار خالی واضح، sort/pagination و نمایش نتیجه |
| فیلتر | فاصله و چینش منظم، عنوان فیلد، reset، تعداد فیلتر فعال، حفظ فیلتر هنگام بازگشت و جست‌وجوی قابل پیش‌بینی |
| input و dropdown | ارتفاع و label یکدست، focus، مقدار انتخاب‌شده و خطا، جست‌وجو و وضعیت خالی، popup بدون clipping |
| دکمه‌ها | یک اقدام اصلی روشن، عملیات فرعی و خطرناک متمایز، loading و جلوگیری از ارسال دوباره، ترتیب منطقی RTL |
| جزئیات | عنوان و وضعیت، شناسه و اطلاعات اصلی، تب و ارتباطات، timeline، شواهد و عملیات دارای مجوز |
| فرم و modal | گروه‌بندی، خطای کنار فیلد، پیمایش و focus درست، بازگشت بدون از دست رفتن اطلاعات و تأیید حذف |

تمام جزئیات فروشگاه، مشتری/کلاینت، ساختمان و مجموعه، آسانسور و قطعه، ویزیت، پرسشنامه، تیکت و کالا باید بررسی شوند. صفر، false، نبود اطلاعات، مجوز نداشتن و خطای دریافت، نمایش‌های متفاوت دارند. پنل فعلی دارای اصلاحات قبلی است؛ هر صفحه با داده واقعی و نمونه‌های لبه بازبینی می‌شود.

## اپ مشترک کلاینت و اکسپرت

- header، back و عنوان صفحه؛ نمایش نقش و پروژه و تغییر آن در حساب چندنقشی، بدون گم شدن زمینه کار.
- منوی بک‌اند بر اساس سطح field و capability، bottom navigation کوتاه و قابل فهم، زیرمنو و صفحه مستقیم با route guard.
- کارت‌های مأموریت اکسپرت با اولویت، نوع خدمت، وضعیت، موعد، ساختمان، نشانی و اقدام ادامه یا شروع.
- کارت ساختمان و آسانسور کلاینت با وضعیت، خدمت باز و موعد؛ مسیر ساده ثبت درخواست و پیگیری.
- جزئیات دارایی، درخواست، گارانتی، تعمیر، گزارش و تیکت با بخش‌بندی و timeline یکدست.
- ویزارد با پیشرفت واقعی، سؤال و پاسخ خوانا، مرحله اجباری و دلیل عدم تکمیل، پیش‌نویس و ادامه کار.
- input و انتخابگر مناسب لمس و صفحه‌کلید، جست‌وجوی گزینه‌ها، انتخاب تاریخ، bottom sheet، خطا و کمک در محل لازم.
- دکمه اصلی در دسترس با safe area؛ نوار پایین، صفحه‌کلید، modal و toast روی اقدام یا محتوای ضروری نیفتند.
- چند عکس، preview و حذف، progress ارسال و retry؛ مجوز دوربین و GPS هنگام نیاز همراه توضیح کاربرد.
- حالت اینترنت ضعیف و قطع شبکه، pending و ارسال موفق، جلوگیری از تکرار و حفظ داده فرم.
- آموزش، موجودی، پشتیبانی، پروفایل و صفحات سرپرست هم شامل بازبینی هستند؛ فقط صفحه tasks یا home کافی نیست.

## شرایط پذیرش بصری

بررسی در عرض‌های ۳۲۰، ۳۶۰، ۳۹۰، ۷۶۸، ۱۰۲۴ و ۱۴۴۰ پیکسل و landscape، با متن فارسی بلند، داده خالی و زیاد، zoom و فونت بزرگ انجام شود. فونت یا breakpoint نهایی پس از نمونه عملی تعیین می‌شود. scrolling افقی فقط برای بخش‌هایی که ضرورت دارند و با کنترل روشن مجاز است.

برای محصول، هدف پیشنهادی لمس حدود ۴۴ پیکسل و focus واضح است؛ این هدف طراحی با حداقل‌های استاندارد اشتباه گرفته نشود. عملکرد صفحه‌کلید، screen reader، برچسب فیلد، اعلان خطا، ترتیب focus و کنتراست بررسی شوند. منابع: [اندازه هدف WCAG](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) و [بازچینی محتوا](https://www.w3.org/WAI/WCAG22/Understanding/reflow.html).

برای هر جزء و صفحه، حالت عادی، loading، empty، error، disabled، success و در موبایل offline ثبت و بررسی شود. شواهد قبل و بعد و نتیجه آزمون در HANDOFF ثبت می‌شود. این سند برنامه پذیرش است؛ آزمون کامل بصری هنوز انجام نشده است.
